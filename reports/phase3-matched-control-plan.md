- `scripts/collect_sft_training_errors.py`：冻结SFT只回答v2训练题，保存原始输出，筛出完整、语义错误且可编码的rejected。`select_error`管筛选和来源，`main`管身份校验、推理、保存、候选隔离审计；`--audit-only`只重算已有结果。

## 结果不够好的可能原因与证据强度

1. **相对偏好目标与生成成功之间存在差距。** 这是直接观察到的现象：chosen与rejected概率都可下降，而后者下降更多；贪心生成面对全部可能回答，训练只比较固定两条。chosen监督项直接增加正确回答的学习信号，但不保证每条概率都上升。
2. **本配置更新幅度/训练步数不合适。** 原B/C长训练退化明显；混合目标固定权重后降低LR能恢复多项指标。证据支持更新稳定性值得关注，不能从混合目标推断纯DPO使用更低LR一定有效。
3. **负例与模型实际错误不匹配。** 38个训练错误只有12个直接匹配原合成负例；真实错误还包含漏项、数字替换、坏JSON。覆盖不足已经核验，但替换负例是否提升生成仍待受控实验。
4. **数据量小、相关性高、覆盖狭窄。** 168对主要来自12个算术family与固定模板，并非168种独立能力；真实候选自然语言29、符号7、顺序2、问候0。增加同模板数据不等于增加有效多样性。不能把“小样本”作为已经证明的唯一主因。
5. **训练与开发分布不同。** v2训练算术数字多为两位数，开发部分为三位数；问法模板仍共享。这可能影响结果，没有隔离数字范围的消融证据。
6. **模型和适配容量、超参数可能限制学习。** 当前为135M模型、rank4且仅q/v的LoRA、单种子，未做容量/seed/beta消融。它们是待验证假设，不是已确认原因。

格式错误会让工具调用直接失败；严格AST也会拒绝数值等价表达式。因此同时报告语义指标和逐题结构变化。原C的语义和结构同样严重退化，不能只归咎于严格评分。

## 本步已经完成：冻结匹配数据与三组方案

新目录`data/preferences/dpo_v3_matched_errors`，不修改原v2：

| 文件 | 内容 |
| --- | --- |
| train_real.jsonl | 38个实际SFT错误作为rejected |
| train_synthetic.jsonl | 同38题的原合成rejected |
| train_chosen.jsonl | 同38题的chosen-only SFT记录 |
| development.jsonl | 原56条开发集原样保留 |
| manifest.json | 身份、文件哈希、来源、隔离/语义/token审计 |
| experiment_plan.json | 三组配置、预算、评估、收益标准和停止条件 |

三组的输入、chosen、target、family、顺序一致。两组DPO只改负例来源；12条负例文本相同、26条不同。跨臂重复是有意的匹配设计，不把它误报为训练/开发泄漏。

| 设置 | 冻结值 |
| --- | --- |
| 起点 | 冻结v2 SFT，base＋原adapter |
| 三组 | chosen-only SFT、合成负例纯DPO、真实负例纯DPO |
| 每组步数 | 38，一轮，每个chosen一次 |
| LR / seed / clip | 1e-5 / 42 / 1.0 |
| 优化器 | AdamW，weight_decay=0，无scheduler |
| DPO beta / chosen NLL权重 | 0.1 / 0，两组均为纯DPO |
| CPU / 最大训练长度 | 2线程、float32/eager / 192 |
| 生成评估 | 沿用基线贪心64 token，五组146记录/145唯一输入 |
| 超参数追加尝试 | 0 |

选择1e-5是基于已有退化经验的保守决定，不是已证明最优；38步可能学习不充分。结论只适用于这组冻结条件。三组chosen曝光相同，但处理token量和训练秒数不同，必须分别记录，不能称算力完全相等。

原56条开发集仍含合成rejected，固定偏好loss可能偏向其来源；生成行为为主要比较依据，不用该loss挑选模型或训练步数。新训练不接触开发标签梯度。

预先判定：先检查冻结/更新/重载等实验正确性。候选需新集严格≥36且语义≥44、各旧组严格不低于基线、所有组无新增逐题JSON/schema/路由或上限退化。若要称DPO提供额外收益，还需相对本轮chosen-only SFT的新严格和语义都不低、至少一项提高，旧组严格不低且无新增逐题结构/上限退化。真实/合成DPO直接对照报告改善/退步，不凭一两个开发变化声称普遍规律。不自动替换baseline。

停止条件：只做三次训练与一轮共同生成评估，不追加LR/beta/anchor扫描；若无DPO额外收益，记录该条件下的负结果，收尾这条Phase 3改进线。
