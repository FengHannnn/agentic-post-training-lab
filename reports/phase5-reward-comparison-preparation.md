# Phase 5：等价二元与分级奖励的有限训练对照

本轮将离线奖励探索接入真实GRPO训练，比较“只接受可验证等价表达式的二元奖励”和“在此基础上增加0.1/0.3部分分”。两个分支从同一个累计31步候选及同一份Adam状态独立起步，使用相同768条温度1.0回答，每组最多6次逻辑更新，不自动选择赢家或晋升基线。

当前状态：实现、CPU输入与权重/Adam预检、400项测试均已通过；云端训练尚未执行，不能预先声称奖励修改带来了训练收益。本地仅用小型测试模型验证反向和恢复，未对项目135M候选执行本轮训练或模型前向。

## 本轮控制的变量

| 项目 | 等价二元分支 | 分级分支 |
| --- | --- | --- |
| 起点 | 同一个31步候选 | 同一个31步候选 |
| Adam | 同一份父动量，累计31步 | 同一份父动量，累计31步 |
| 满分条件 | 严格通过或可验证交换律等价 | 相同 |
| 错误回答 | 0 | 符合门限时0.1或0.3，否则0 |
| 数据 | 同一24题×32条，温度1.0 | 相同 |
| 顺序与预算 | 固定6批，每批4题×32条 | 相同 |
| reference | 原始冻结SFT | 相同 |

满分仍要求完整合法calculator调用、表达式验证及数值正确，不能仅看数值碰巧相同。评分器与已经离线验收的版本一致，源码摘要写入计划；交换律范围、数字/运算多重集合及部分分规则未在本轮临时更改。

等价二元有16个非零方差组，分级有24个。为保证数据和计算预算可比，两组都完整处理24组，不分别筛选16与24组。等价二元中零advantage回答的策略奖励项为零，但仍保留相同的原SFT KL项；不能说这些回答完全不参与损失。每批保留原生回答长度、EOS和截断，无效JSON同样保留。

每个分支最多6步，每道题只在一次正式批次中出现。第2步额外执行一次恢复对照，丢弃连续路径后从第1步检查点恢复，核对重做第2步的结果，因此成功时每组实际7次optimizer.step调用、896次逐回答反向，但只提交6步逻辑更新、处理768条正式训练回答。两个分支各自从31到37，不是串接为31到43。

6步和4个family的规模用于寻找方向，不足以直接证明显著提升。两个分支均只有一个固定seed，结果需同时看开发集、错误类型和结构退化，不能仅凭训练奖励均值判断。

## 为什么可以复用本批回答

采样源为`artifacts/trajectories/grpo-exploration-20261028-01`中的`t100`分支。采样时策略就是现在仍未更新的31步候选，完整参数摘要为`70804ab1c9344f7578396e4ccaa90dfe1ea374c69f96cb69ee3970d036eedf7d`。因此本轮无需重复随机生成。

只准入温度1.0且behavior logp与原始模型logp含义一致的768条记录。1.3和1.6不进入训练。原离线评分输出仍标为未准入训练；本轮通过新的版本绑定、同路径概率检查与冻结reference检查后，在独立训练上下文中使用这些原生回答。

共享prepare阶段使用GPU FP32 eager重新计算每条回答的trainer_old、保留梯度的新策略logp和冻结SFT reference logp。所有768条都必须通过初始old/new门；不把vLLM FP16原始logp直接当成FP32 trainer_old。原跨引擎门失败的事实保留，继续使用原有token TIS、cap=2、PPO clip=0.2和近似sampled k3，不能把这次接入解释为修复了跨引擎等价性。

prepare不调用backward、不更新参数，缓存来源和全部内容以summary摘要绑定。每组开始前再次对全部768条重算FP32 old logp，与共享缓存核对，防止第二组误接第一组的权重或概率。共享reference缓存始终保持原SFT，不随任一分支更新。

不在更新后自动重采样，也不继续第二轮训练。如果后续决定继续更新，仍需要从相应新策略刷新rollout。

## Adam与恢复

父检查点位于`artifacts/checkpoints/grpo-iteration-20261028-01/final-checkpoint`。它的本地逻辑步数为15，Adam张量累计计数为31；两者分别验证。父optimizer文件SHA256为`5183dfbca54f1f54c4e1d8baee90f340556907c4a4755643cc033c16a0979db7`。

两个分支分别验证父文件哈希、输入binding、参数名与顺序、超参数、状态覆盖、moment形状/精度/有限性/二阶矩非负及计数，再导入同一份moment。分支binding包含共享准备结果摘要和arm名，因此不同分支不能互相恢复。父RNG不导入，每组使用同一个新seed独立初始化；组内恢复则恢复该分支自己的RNG和binding。

本地CPU已完整重建135M候选，核对120个可训练LoRA张量、230400个参数和全部参数摘要；真实父Adam导入最大误差为0。小型模型测试进一步验证了31步动量导入、两套奖励下真实反向更新，以及保存/恢复后下一步参数和Adam状态一致。

## 保留的训练门限

学习率1e-5、beta=0.02、TIS cap=2、clip epsilon=0.2、梯度裁剪1.0。继续调用原`guarded_step`，sampled k3超过0.05或ratio clip fraction超过0.5时停止；非有限或零LoRA梯度失败。保留串行逐回答反向，未启用此前未通过概率门的微批训练。

每组要求基础参数不变、冻结参数无梯度、同起点参数身份正确、恢复对照通过、最终adapter重载后的logp和固定贪心token一致。共享prepare还会重新生成原SFT与31步候选的104条评测，并核对其token与既有保存预测一致，避免把起点评测路径变化当作训练变化。

任一阶段失败或任一组未完成6步，后续阶段停止并保存实际证据；不能将未完成的两组比较当作有效结果。行为安全门单独记录，失败也不会自动晋升或接着训练。

## 评测与结果判读

沿用48条训练诊断和56条开发集，训练数据只来自既有24道训练题。开发集保持隔离。原SFT、31步起点、两个更新分支都按相同两套主指标报告：原严格通过数与新验证正确通过数，同时记录完成后的语义通过、格式退化和截断。

起点开发集旧严格为36/56，新验证正确口径为44/56。只有在同口径下对起点或另一个分支改善，才可讨论训练收益；不能把36变44的口径变化作为收益。训练平均奖励也不能代替开发集正确率。

重点比较分级分支相对等价二元的新增正确题、退步题，以及无满分样本的8道自然语言题是否改善。若只改善格式、仍遗漏计算步骤，应明确记录。即使本次有净增，也还需要根据幅度、稳定性和题目变化决定是否扩大验证；本轮不自动宣布显著提升。

## 云端执行

增量包为`grpo-reward-comparison-20261028.zip`。依赖云端已有31步候选、原SFT及模型缓存、两轮训练依赖，以及上次探索的完整目录仍保留。不需要上传本地4920条重评分产物；新脚本会从被固定摘要绑定的原始温度1.0回答重新计算奖励。

把ZIP上传到`/root/rivermind-data`或其项目子目录。以下命令会在这两层中查找准确文件名，避免再次因上传位置不同而找不到ZIP；解压成功才启动训练：

```bash
conda activate /root/rivermind-data/envs/apt-vllm
cd /root/rivermind-data
ZIP_PATH=$(find /root/rivermind-data -maxdepth 2 -type f -name 'grpo-reward-comparison-20261028.zip' -print -quit)
test -n "$ZIP_PATH" && \
python -m zipfile -e "$ZIP_PATH" . && \
cd AgenticPostTrainingLab && \
python scripts/run_reward_comparison.py --hourly-price 2.18
```

如果当前小时价格不同，修改最后的2.18；如果查找结果为空则不会执行解压和训练，需核对实际上传位置/名称。

prepare、等价二元训练、分级训练及audit合计使用一次30分钟与10元对应时长的较小预算，预留10秒清理；2.18元/小时对应1790秒。不是每个分支各30分钟。预算不包含预检、打包、启动、闲置、存储和计费取整，脚本不自动关闭实例、不自动延长或重试。完成后请停止实例。

进入有限阶段后无论成功或失败，项目根目录都会尽量生成`grpo-reward-comparison-review-20261028.zip`，请下载并上传给当前对话。如果输入/文件检查就失败，GPU训练尚未启动，可能不会产生结果包。保留错误与已有输出，不要盲目删除目录重跑。

主要结果目录是`artifacts/checkpoints/reward-comparison-20261028-01`，包括`shared/`、`equivalent_binary/`、`graded/`、成功后的`comparison.json`以及`cost_and_run.json`。两个分支均含源快照、history、optimizer lineage、step1与final检查点、恢复/重载检查、预测和summary。已有目录或结果ZIP会阻止重复执行。

## 代码阅读顺序

1. `configs/experiments/grpo_reward_comparison.json`：先看两组共同的24题、6步预算、父身份、奖励版本、优化器与reference边界。
2. `scripts/reward_comparison_common.py::context`和`admit_rewards`：原生温度1.0记录经过审计后转换为统一样本；分别计算二元与分级advantage，保留零方差组。分级只接受已冻结的有限分值，不再误用旧0/1专属校验。
3. `import_comparison_adam`：重点看父本地15与累计31分别核对，moment全覆盖，以及不导入父RNG。
4. `scripts/train_reward_comparison.py::prepare`：读旧/新同路径FP32概率门、冻结SFT缓存、无参数更新，以及原SFT/起点贪心预测重放。
5. `load_shared`与`train_arm`：读缓存摘要binding、每组独立从父起步、完整old检查、相同6批、原串行guarded_step和恢复对照。
6. `evaluation_metrics`、`predictions`、`audit`：读两种正确率口径、已保存预测复算、两组相同预算及最终比较；audit只复核保存证据，不重跑GPU。
7. `scripts/run_reward_comparison.py::dispatch`：读四阶段统一超时、失败停止、实际证据打包和防止重复执行。
8. `tests/integration/test_reward_comparison.py`：先看两组真实更新和恢复测试，再看损坏状态、非法奖励及失败调度测试。
