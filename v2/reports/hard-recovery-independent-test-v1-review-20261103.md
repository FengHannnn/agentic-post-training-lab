测试使用固定 test-000～003 四个任务族，每任务进行 1 次贪心和 8 次温度 0.8 随机完整任务评测。任务 ID、任务族和随机种子与训练、开发任务分离，36 个恢复上下文均未出现在 169 条训练偏好中。该集合沿用项目固定测试任务；后续模型迭代采用训练集扩充、开发集选型，并为最终确认增加新任务族和种子。

**新增双指标均未验证的组合恢复**

新增两类上下文：当月和上月 gross-only SQL 都已执行、均未验证；以及在此基础上又连续两次调用无效证据计算。每模型进行 8 次贪心续跑、24 次随机续跑。

| 指标 | 父模型 | 加权 SFT |
|---|---:|---:|
| 首动作选择 SQL：贪心 | 0/8 | 7/8 |
| 首动作选择 SQL：随机 | 1/24 | 20/24 |
| 首动作取得目标验证：贪心 | 0/8 | 0/8 |
| 首动作取得目标验证：随机 | 0/24 | 0/24 |
| 全程获得任意新验证指标 | 0/32 | 0/32 |
| 完整恢复并提交 | 0/32 | 0/32 |

候选模型已经更倾向于查询，但 SQL 内容仍未完成指标重建。例如直接使用不存在的 current_net_cents 列、把退款额当作 gross_cents，或者只查询月份、订单 ID、订单汇总等辅助数据。贪心 7 次查询中，4 次执行成功但未验证、3 次执行报错，另有 1 个格式错误动作。

随机续跑中出现 6 次达到 256-token 上限的输出，集中于 2 条候选轨迹；全部 288 个首动作都正常停止。截断是一个后续观测项，主要修复目标仍是 SQL 和恢复动作序列：候选全部 32 条续跑均未生成新指标证据。预检中的专家路径对 8 个上下文均用 5 个后续动作完成，且都处于相同的 12 步总预算内。

结合当前训练数据覆盖，较强的行为是“已有另一月有效证据时重查缺失指标”及“错误 SQL 执行后的重查”；双月查询都执行但均未验证的组合，是这次暴露的主要覆盖缺口。该判断来自场景对照和动作内容。

**跨月退款 SQL 校验**

将模型已通过环境验证的 SQL 放到两个金额、退款月份重排的数据世界中重新执行，检查退款按退款月归属、与订单发生月份独立的业务口径；并追溯最终提交所用证据。这是补充 SQL 语义校验。

父模型完整任务的 56 条已验证查询、候选的 64 条全部通过两个世界的校验。成功提交数与跨月口径一致的成功数相同：父模型贪心 4、随机 24；候选贪心 4、随机 28。恢复首动作中的已验证查询也全部通过：父模型 1 条、候选 43 条。双指标组合恢复中尚无已验证 SQL。
