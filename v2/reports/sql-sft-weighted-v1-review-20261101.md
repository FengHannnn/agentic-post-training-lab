## SQL 与证据链的实际变化

成功路径为：read_policy → inspect_schema → query_sql（本月）→ query_sql（上月）→ calculate_change → check_result → submit。故障任务在首次 query_sql 后增加一次重试。

32 条有效月度 SQL 均通过原数据和扰动数据库验证，去掉空白后与对应专家 SQL 完全一致。查询中正确使用 paid 订单、订单月份、退款发生月份及地区/客户群限制；本月与上月分别查询，真实 qN 证据用于计算，计算返回的 cN 用于最终提交。

例如 train-000：本月 19,808 cents，上月 24,382 cents，差额 -4,574 cents；7 轮完成检查和提交。

## 结果范围与接续

当前结果来自一个合成业务对账任务族的 12 个训练任务和 4 个开发任务，greedy 单次执行；独立 test 尚待模型评测。

建议下一步先用保留的 4 个 test 任务完成独立评测，再将这个 126-step 候选冻结为后续 DPO 与 GRPO 的共同 SFT 起点。正式扩大效果比较时，增加任务和 family 覆盖，并预先确定评测方案。

可选分支：等预算均匀权重对照，用于分析加权贡献；新增 SQL 验证为空及月份混淆修复示范，用于后续更广任务覆盖。
