## 1. 目标和范围

目标：约一周半、每天平均 6 小时，约 10 天 / 60 小时内形成可投递成果。首选大模型后训练 / 强化学习算法实习，其次 Agent 开发。日程按实际开始实施的日期计算；第 7 天检查进度并冻结新增功能，最后约 3 天用于评测和交付。

必做：有边界的 DPO 补验；结果奖励 GRPO；一套可验证进展加逐轮 return/advantage 的细粒度分配方法；一种具有前后证据依赖的轻量 SQLite 业务对账扩展；可靠的实验对照和面试材料。

可选：GDPval、多文件办公环境、网页界面、额外局部恢复训练分支、更多奖励算法与大规模调参。Multi-OPD 排除。当前演示采用报告、终端或录屏。

当前主线保留已有 SQL 环境和结果，逐步增加依赖深度。无需重建文件 Agent 平台或重新完成首轮 SFT。

## 4. GRPO 的共同起点与技术重点

用户已确认：结果奖励 GRPO 和细粒度 GRPO 均从当前 hard-recovery-sft-weighted-v1-20261103 出发。SHA256 为 f8fb95a4135af76398a1ab9c84f49b8f90b7e30ce77cc50a4b59f863202d689f，履历为 SFT513 / DPO11。历史纯 SFT 基线独立保留。DPO 补验结果和本轮 GRPO 对照分开汇报。

当前 trainer.py 有逐动作 PPO 更新内核，正式 GRPO 仍需补齐组内优势定义、零方差组策略、原生行为概率、有限预算的训练 runner、old/ref 缓存、策略刷新及断点恢复。

先用实际轨迹做显存和吞吐预检；已验证 8192-token 推理和 512-token 双模型训练探针，完整长上下文 RL 容量由新预检确定。概率角色保持 q / p_old / p_new / p_ref 分明，旧 DPO 轨迹的 raw logprob 不直接充当 RL 的行为概率。

第一版细粒度机制：验证首次进展，计算逐轮 return/advantage，将信用分配给该动作的 response token。现有 gamma=1 且终局 potential 清零时，过程奖励整条轨迹总和为 0，必须实际改变逐轮训练信用并与轨迹级优势比较。重复验证同一指标保持原进度。
