## 开发集恢复上下文

开发集4个任务 × 7类，共28个上下文，与训练task/family分离。每模型每上下文贪心1次、随机3次。指标为下一步动作是否带来新增验证进展或检查通过。

| 恢复场景 | 贪心前/后（各4次） | 随机前/后（各12次） |
|---|---:|---:|
| 格式错误后恢复 | 4 → 4 | 6 → 7 |
| 未知工具后恢复 | 4 → 4 | 12 → 12 |
| SQL未验证后重新查询 | 0 → 0 | 0 → 0 |
| 连续证据错误后恢复 | 0 → 0 | 0 → 0 |
| 错误证据编号修复 | 4 → 4 | 11 → 12 |
| 连续SQL错误后恢复 | 0 → 0 | 0 → 0 |
| 检查失败后修复 | 0 → 0 | 0 → 0 |
| 合计 | 12/28 → 12/28 | 29/84 → 31/84 |

随机恢复严格格式动作均为79/84；重复上一动作次数从15增至16，贪心重复次数从4增至6。证据编号修复和格式场景略有提升；四类需要切换处理步骤的场景继续失败。

本地逐条观察：缺少已验证指标时，模型仍倾向调用calculate_change；连续证据错误后继续原动作；连续SQL错误后仍使用错误表/字段；检查失败后转入错误的差额计算。下一轮应以这些场景的动作选择变化作为主要指标。
