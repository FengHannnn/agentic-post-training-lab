## 变化轨迹

- test-000 / rollout 7：SFT 使用 SQLite 不支持的 EXTRACT 语法并反复重试；DPO 使用通过验证的净额查询，7 轮提交成功。
- test-001 / rollout 1：SFT 从 orders 引用 refund_cents，并反复重试；DPO 正确关联 refunds 和 orders，临时故障后重试成功，8 轮提交。
- test-003 / rollout 7：SFT 完整成功；DPO 将退款发生月份条件改成订单月份条件，上月指标未通过验证后仍重复调用 calculate_change，最终耗尽 12 轮。

## 验证器覆盖观察

退化轨迹中的本月 SQL 也使用了订单月份筛选，但本月指标仍通过现有验证。复核数据库后发现：本任务中，按本月退款月份筛选和按上月订单月份筛选都命中 refund_id=13。现有两次扰动仅改变金额，保留月份关系，因而该查询在三个数值世界中得到相同结果。

后续可增加订单月份与退款月份关系的结构扰动，覆盖同月订单跨月退款、跨月订单当月退款等组合。这属于验证环境增强，应与模型续训作为独立改动记录。
